### 1. PROJECT OVERVIEW

**Toolsy** is a modular Next.js developer tool platform built with TypeScript, Tailwind CSS, and Framer Motion. It hosts independent tools (SSL toolkit, JSON formatter, malware analysis, data converters) under a unified futuristic UI with glassmorphism aesthetics. Tools reside in `app/tools/[category]/` as route-based modules with centralized metadata registry.

---

### 2. ARCHITECTURE

**Directory Layout:**
- `app/` — Next.js App Router pages and API routes. Top-level `app/page.tsx` is the homepage; `app/tools/` contains tool categories and individual tool routes.
- `app/tools/` — Each tool has two files: `page.tsx` (server component + redirect) and `client-page.tsx` (interactive UI).
- `app/api/` — Server-side API routes (e.g., `app/api/threat/` for VirusTotal integration).
- `components/` — Shared components split into `home/` (Hero, SmartInput, ThemeToggle), `tools/` (ToolContainer, ToolHeader, ToolButton, ToolTextarea), and `ui/` (GlassCard).
- `lib/` — Central registry (`tools.ts`) powering navigation, routing, and metadata.

**Entry Points:**
- `app/layout.tsx` — Root layout with Geist fonts and AppLayout wrapper.
- `app/page.tsx` — Home page (HomePage) with radial menu and atmospheric layers.
- `app/tools/page.tsx` — Tools index (ToolsIndexPage) with category tabs and search.

**Module Relationships:**
`lib/tools.ts` exports `toolCategories` and `categoryList` — these are consumed by `app/tools/page.tsx` (for filtering), `app/tools/[category]/page.tsx` (for SSG params), and `components/home/SmartInput.tsx` (for tool suggestions). Tool client components are independent; they only share UI primitives from `components/tools/`.

### 4. PATTERNS & CONVENTIONS

**Client/Server Separation:** Tool UIs live entirely in `*-client.tsx` files (React `'use client'`). Server pages (`page.tsx`) only handle metadata, redirects, and rendering of the client component. Never put interactive logic in server pages.

**Redirect Pattern:** Individual tool `page.tsx` files redirect to categorized paths:
```tsx
// app/tools/ssl-toolkit/page.tsx
// → /tools/network-security/ssl-toolkit
```
Keep these redirects; they preserve backward compatibility and SEO.

**Tool Structure Convention:** Each tool follows:
1. `app/tools/[category]/[tool-slug]/page.tsx` — Server page (metadata + client render)
2. `app/tools/[category]/[tool-slug]/client-page.tsx` — Client component (all logic)

**UI Composition:** Use `ToolContainer` → `ToolHeader` → `ToolSection` → `ToolButton`/`ToolTextarea` hierarchy for consistent tool pages.

**Styling:** Apply glassmorphism via `.glass-*` utility classes from `app/globals.css`. Theme colors come from CSS custom properties defined in `tailwind.config.ts`.

**Async/API:** API routes (`app/api/`) use Next.js App Router handlers. Client components use `fetch` or direct API calls (e.g., ThreatInspectorClient calls `/api/threat/upload`).

### 5. CRITICAL DEPENDENCIES

**Tools Registry (`lib/tools.ts`)** is the single source of truth for tool metadata. Every consumer depends on it:
- `app/tools/page.tsx` — imports `categoryList` for tab generation
- `app/tools/[category]/page.tsx` — imports `toolCategories` for filtering
- `app/tools/*/client-page.tsx` — imports `toolCategories` for metadata (e.g., SSLToolkitClient uses `#ssl,certificate,pem`)
- `components/home/SmartInput.tsx` — uses `toolCategories` to suggest tools based on detected content

**Shared Tool UI Components** (`components/tools/index.ts`):
```
ToolContainer → wraps page layout
ToolHeader → displays title, description, category badge, back nav
ToolSection → card-style container for grouped content
ToolButton → action buttons with variants
ToolTextarea → styled input/output with character count
```
All tool client-pages should import from this barrel export.

**Theme System:**
- `app/globals.css` defines CSS variables (e.g., `--toolsy-accent`)
- `tailwind.config.ts` references these via `var()` for Tailwind utilities
- `components/home/ThemeToggle.tsx` manages light/dark via localStorage

**Animation Library:** `framer-motion` powers all animations. `components/ui/GlassCard.tsx` provides animated glassmorphism cards; `components/home/Centerpiece.tsx` uses motion for the orbital effect.

### 6. MODIFICATION RULES

**MUST preserve:**
- `lib/tools.ts` exports — any tool addition/removal must update this registry; the homepage radial menu and SSG `generateStaticParams` depend on it.
- Client component boundaries — `'use client'` directives are intentional; moving interactive code to server components will break functionality.
- Redirect pages (`app/tools/*/page.tsx`) — removing them breaks existing URLs and SEO.

**MUST NOT break:**
- `app/globals.css` class names (`glass-*`, `toolsy-*`) — used across all components. Renaming requires updating every consumer.
- API route signatures — `ThreatInspectorClient` calls `/api/threat/upload` and `/api/threat/hash/[hash]` directly; changing paths breaks the tool.
- TypeScript strict mode (`tsconfig.json`) — the project uses `strict: true`; type errors will block builds.

**When adding a new tool:**
1. Add entry to `lib/tools.ts` with category, slug, title, tags, description.
2. Create `app/tools/[category]/[tool-slug]/page.tsx` (server page) and `client-page.tsx` (client component).
3. Optionally add redirect from `app/tools/[tool-slug]/page.tsx` to the categorized path.
4. Use `ToolContainer` + `ToolHeader` + `ToolSection` for consistent layout.

**Avoid:** Adding global CSS without checking `tailwind.config.ts` for variable conflicts; placing client-side logic (useState, useEffect, event handlers) in non-client components.
